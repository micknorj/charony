The safety audit traced every production deletion entry point. Apps creates paths only from one explicitly selected application UUID and the fixed Documents/Library/tmp parts. It captures device/inode identity and bundle identity, validates all parts before mutation, rejects traversal and symlinks, excludes Charony's own container, retains container/part roots and checks postconditions. Cache cleaning permits exact app/extension parents and the fixed Library/Caches/tmp paths, performs whole-batch preflight, validates before each mutation and serializes operations across tabs. Crash removal permits only the two upstream report directories, with canonical/no-link ancestry and scanned directory identity. The test override for crash roots exists only in the simulator fixture compilation. Cache cancellation is cooperative between filesystem items and navigation cancels an active cache clean. Apps confirmation cancellation enters no worker. Full app clearing follows the upstream accepted permanent-clear behavior and has no Stop button.

Removing backup/restore implementation did not remove a required clear-without-backup rollback transaction. That upstream path already purged permanently. Its retained safety is selection, identity and path validation, descriptor-relative traversal, cancellation where supported, root preservation and explicit partial failure. Backup-storage guards, copy verification, restore manifests and restore journals belonged to removed operations. No remaining production caller can create a file/app backup or enter those removed APIs. The App Group cache-swap marker, preserved directory and recovery protocol remain because they protect access setup. Nine relevant upstream safety helpers, including the restored directory-creation pair, are compared with the stable object. These are operational recovery mechanisms.
